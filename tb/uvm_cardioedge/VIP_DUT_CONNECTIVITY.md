# CARDIOEDGE SoC — UVM VIP to DUT Connectivity Mapping & Architecture

## Overview
This document specifies the exact physical and protocol-level signal connections between the four Universal Verification Methodology (UVM) Verification IP (VIP) interfaces and the `cardioedge_cpu_soc_top` SoC Device Under Test (DUT).

---

## 2. Direction Analysis & Protocol Perspective

### SPI Master vs. Slave
- The CardioEdge SoC incorporates an SPI Master Controller (`rtl/spi/axi_spi_top.v`).
- Therefore, the SPI VIP operates as an **SPI Slave**.
- `spi_clk_o`, `spi_cs_n_o`, and `spi_mosi_o` are generated by the SoC DUT and monitored by the VIP.
- `spi_miso_i` is driven by the SPI VIP into the SoC DUT synchronously with `spi_clk_o` when `spi_cs_n_o` is asserted (low).

### UART Transmit vs. Receive
- The CardioEdge SoC includes a full-duplex UART Controller (`rtl/uart/axi_uart_top.v`).
- `uart_rx_i` is an input to the SoC: driven by the UART VIP driver (VIP Tx -> DUT Rx).
- `uart_tx_o` is an output from the SoC: monitored by the UART VIP monitor (DUT Tx -> VIP Rx).
- Baud rate timing is synchronized to 1280 ns (50 MHz clock with BAUD_DIV = 4 and 16x oversampling).

### GPIO Bidirectional Handling
- The SoC top module exposes `inout wire [GPIO_BITS-1:0] gpio_io`.
- When the CPU configures pins as outputs (`reg_dir = 0xFF`), the DUT drives `gpio_io`. The testbench holds `gpio_drv_en = 0` (high-Z) to prevent bus contention.
- When external stimulus is tested, the GPIO VIP asserts `gpio_drv_en` and drives `gpio_in`, verifying input path reception without floating pins or multiple drivers.

## 3. DUT Input Tie-Offs & Floating Pin Prevention

To ensure no input is left floating and no multiple drivers exist:
- `clk`: 50 MHz free-running clock generator (period = 20 ns).
- `rst_n`: Active-low clean reset driven by testbench control process.
- `timer_ext_meas_i`: Tied to `1'b0`.
- `timer_capture_i`: Tied to `1'b0`.
- `fir_s_axis_tvalid`: Tied to `1'b0`.
- `fir_s_axis_tdata[15:0]`: Tied to `16'h0000`.
- `fir_m_axis_tready`: Tied to `1'b1` (always ready to receive FIR output samples).
